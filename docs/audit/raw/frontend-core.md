# Audit slice: frontend-core

## Purpose (what this slice does)
This slice is the app shell and shared infrastructure for the Weapon Fitness Expo/React-Native-Web client:

- **App.js / index.js** — root component; requests notification permissions on mount, wraps the tree in `ErrorBoundary > SafeAreaProvider > ThemeProvider > AppNavigator`.
- **app.config.js / babel / metro / tsconfig / eas** — Expo build config. Loads `.env` via `dotenv/config` and exposes Supabase + SMTP secrets through `expo.extra`. Metro is customized for SVG via `react-native-svg-transformer`.
- **navigation/** — a single flat `createNativeStackNavigator` (`AppNavigator`) with 13 screens and five role-specific `createBottomTabNavigator` tab files (Admin/Owner/Receptionist/Trainee/Trainer).
- **config/** — `api.js` (base-URL resolver, hardcoded ngrok), `apiClient.js` (fetch wrapper + `api.{get,post,...}` helpers), `supabase.js` (Supabase client with custom storage adapter).
- **constants/** — `theme.js` (dark/light palettes + spacing/typography/layout), `colors.js` (a second, unrelated maroon palette `colors2`), `api.js` (email endpoint constants).
- **context/ThemeContext.js** — `isDark` state + `toggleTheme`, persisted to AsyncStorage.
- **utils/** — `rateLimiter.js` (calls a Supabase Edge Function `rate-limit-demo`) and `SecureStoreAdapter.js` (SecureStore on native, localStorage on web).

## What actually works
- The provider nesting in `App.js` is correct (ErrorBoundary outermost, ThemeProvider above the navigator). StatusBar `style="auto"` is reasonable.
- `SecureStoreAdapter` is a clean, correct platform shim and is wired into the Supabase client as its session store.
- `ThemeContext` correctly persists the preference and exposes `colors/isDark/toggleTheme`; `useTheme` is consumed by ~54 screens/components, so the runtime color side of theming is broadly adopted.
- `apiClient.apiRequest` has thorough response handling: 204 / empty-body / non-JSON / JSON, and flattens FastAPI 422 `detail` arrays into readable messages.
- `metro.config.js` SVG transformer setup is standard and correct.
- The Edge Function `rate-limit-demo` (the server side of `rateLimiter.js`) does implement real per-path sliding-window limits keyed by JWT-or-IP.

## UI & design notes
- **Two competing color systems confirmed:** `constants/theme.js` (live; charcoal `#0F0F0F` / red `#E50914`, with full dark+light token sets) vs `constants/colors.js` (`colors2`, a maroon `#1a0e0e` set that is exported but imported nowhere). The app's branding (`app.config.js` splash `#8B0000`, dark `userInterfaceStyle`) matches neither exactly — splash is a third red.
- **Theme toggle is half-wired:** runtime colors flow through `useTheme()` in ~54 files, but `typography` and `layout.glass` in theme.js are computed once against the dark palette and consumed statically, so toggling to light leaves text/glass chrome dark. All five tab bars use static `colors`, so the bottom navigation never changes with theme.
- Tab bars across all five role navigators are copy-pasted identical glass styling (floating, `bottom:20`, radius 24, height 70) — good visual consistency but heavy duplication (one shared `tabBarStyle` would do).

## Dead code & hygiene
- `constants/colors.js` — entirely unused.
- `utils/rateLimiter.js` `checkRateLimit` — no callers.
- `AppNavigator` imports unused `OwnerDashboard`; ships `Test`/`TestScreen`.
- `TraineeTabs` placeholder wrappers carry dead `useState`.
- Inline `require` for `PaymentsScreen` only.
- Root repo is full of one-off debug scripts (`check_*.js`, `debug_*.js`, `probe_*.js`, `stash*_trainee.js`, `fix_trainer*`, `inspect_db.js`, etc.) — not in this slice's file list but they surround it and should be quarantined (Phase 5).

## Cross-slice questions (for other slices to confirm)
1. **Backend-auth slice:** Does FastAPI (`backend/main.py` routers) actually verify the bearer token? If apiClient never sends one (`useAuth` defaults false and no caller sets it), either every endpoint is open (confirms S3 IDOR severity) or auth is fully bypassed. Confirm whether any dependency enforces auth.
2. **Email slice:** Confirm the Receptionist email flow target. `ENDPOINTS.SEND_EMAIL` resolves to the FastAPI base (`:8000`/ngrok) but `/api/email/send` only exists on the Node server (`server/index.js:47`, default port 5000). Is there a reverse proxy mapping `/api/email` from 8000→5000, or is this simply broken?
3. **Screens slice:** Several screens call `supabase.functions.invoke('rate-limit-demo', ...)` directly (per grep of 17 files). Confirm whether those pass the `x-action-path` header correctly and whether the Edge Function (`supabase/functions/rate-limit-demo/index.ts`) is even deployed against the dead Supabase project.
4. **Edge-function slice:** `rate-limit-demo/index.ts` does far more than rate limiting — it performs privileged writes (create_trainee/add_trainer with default password "12345678" at :388, manage_plans, delete_group) using the SERVICE_ROLE key and trusts `payload` IDs without verifying the caller's JWT matches (self-documented at :950). Confirm this is treated as a CRITICAL backend finding in the appropriate slice.
