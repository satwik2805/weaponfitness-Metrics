# Audit: screens-auth-profile

Files audited (every line read): `screens/WelcomeScreen.js` (176), `screens/LoginScreen.js` (148), `screens/LoadingScreen.js` (217), `screens/EditProfileScreen.js` (271), `screens/ProfileScreen.js` (470), `screens/TestScreen.js` (205), `screens/AdminProfileScreen.js` (312), `screens/OwnerProfileScreen.js` (279), `screens/ReceptionistProfileScreen.js` (289), `screens/TrainerProfileScreen.js` (334). Cross-referenced: `navigation/AppNavigator.js`, `services/profileService.js`, `config/supabase.js`, `app.config.js`, `package.json` (react-native-web ^0.21.0, React 19.1.0).

## Purpose

This slice is the entire auth funnel and the five per-role profile surfaces:

- **WelcomeScreen** — animated landing page, routes to Login; also ships a "Test Backend Connection" link to TestScreen.
- **LoginScreen** — email/password sign-in via `supabase.auth.signInWithPassword`, plus a stub "Continue with Google" button.
- **LoadingScreen** — post-login splash: reads the Supabase session, fetches the profile role (backend API first, Supabase fallback), and routes to one of five role tab navigators.
- **TestScreen** — developer API smoke-test screen (ping, list profiles, list branches), registered in the root stack and reachable pre-auth.
- **ProfileScreen** (Trainee) + **Admin/Owner/Receptionist/TrainerProfileScreen** — view profile, branch, stats; Edit Profile; Link Gmail (`linkIdentity`); Logout.
- **EditProfileScreen** — shared editor for name/phone/avatar; avatar upload to Supabase Storage bucket `profile_images`.

## What actually works

- Role routing architecture is coherent: Login → Loading → role-switch → `navigation.replace` into the right tab navigator, all route names match `navigation/AppNavigator.js:33-46`. Logout's `navigation.replace("Login")` from inside tab screens correctly bubbles to the parent stack.
- LoginScreen has genuinely careful error handling *for native*: validates empty fields, surfaces `error.message`, even re-checks the session after a 500ms grace period (LoginScreen.js:47-58). The logic is right; the delivery channel (Alert) is what's broken on web.
- ReceptionistProfileScreen is the best-behaved variant: guards `userId` (line 34), captures email from the session synchronously (line 37), shows a real ActivityIndicator while loading.
- TrainerProfileScreen actually handles a missing session by resetting the nav stack to Login (lines 31-36, 71-77) — the only profile screen that does.
- ProfileScreen's streak algorithm (lines 144-178) correctly dedupes same-day entries, handles 0-day gaps, and breaks on >1-day gaps.
- The backend-first / Supabase-fallback pattern in LoadingScreen and EditProfileScreen is a reasonable resilience idea (even though both backends are currently dead).
- Theming: four of five role screens correctly use `useTheme()` + `createStyles(colors)` + `useMemo`.

## UI & design notes

- WelcomeScreen is the strongest visual in the slice (animated hero, glass card) but the underlined gray "Test Backend Connection" dev link directly under the CTA undermines it.
- LoginScreen has no "Forgot password", no sign-up path, no show-password toggle, and the loading state doesn't disable the button (double-submit possible: LoginScreen.js:119-121).
- TestScreen uses a completely different light theme (`#f5f5f5`/`#007AFF`) from the rest of the app — clearly a scaffold screen.
- Five visually near-identical profile screens have drifted: different avatar sizes (110/120/130), different loading affordances (text vs spinner), Admin off-theme, Trainer's Link Gmail text style wrong. A single themed base screen would fix all of this at once.
- Logout button text uses `colors.text` while its icon uses `colors.error` on four screens — half-styled danger affordance.

## Cross-slice questions

1. **api-client/services slice**: confirm `GET /profiles` and `GET /branches` require no auth server-side (FastAPI routers) — TestScreen makes this an anonymous one-tap enumeration if so (extends S2/S3).
2. **backend routers slice**: what casing does the DB `profiles.role` column actually use? LoadingScreen matches `"Trainee" | "Trainer" | "Receptionist" | "Owner" | "Admin"` exactly (LoadingScreen.js:94-109) — verify seed data matches.
3. **storage slice**: does the Supabase `profile_images` bucket have public read + authenticated-write-own policies? EditProfileScreen uploads with `upsert: true` to a path keyed only by userId+ext (EditProfileScreen.js:82) — different extensions create multiple orphaned files per user.
4. **navigation slice**: confirm no `linking` config exists on NavigationContainer; if web URL linking is ever added, the `Test` route becomes directly addressable by URL.
5. **dashboards slice**: do the role dashboards also duplicate the Supabase-direct vs services/ split seen here?
6. **theme slice**: `constants/theme` static `colors` vs `ThemeContext` colors — AdminProfileScreen and WelcomeScreen/LoginScreen/LoadingScreen all use the static export; verify which screens break when the theme toggles.
