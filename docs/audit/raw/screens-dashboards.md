# Audit: screens-dashboards

Files: OwnerDashboard.js (1941), AdminDashboard.js (1121), TrainerDashboard.js (677), ReceptionistDashboard.js (399), ReceptionQRCodeScreen.js (53), TodayAttendanceScreen.js (172), PaymentsScreen.js (425). All lines read.

## Purpose

Role-based home screens. OwnerDashboard: multi-branch KPIs (members/trainers/receptionists/expiring), revenue snapshot + 6-month trends, attendance chart, trainer ratings, plan-tabbed member list, quick-action modals. AdminDashboard: global stats, user directory with delete, payment log, branch list. TrainerDashboard: assigned trainees (streak/BMI/completion), groups, workout/diet assignment modals, conditional renewal. ReceptionistDashboard: member search, register/renew, QR attendance, broadcast email. ReceptionQRCodeScreen: static gate QR. TodayAttendanceScreen: today's check-ins. PaymentsScreen: owner payment history with status filter.

Data wiring is a hybrid: Admin/Today/Payments and Owner's branch list try the FastAPI backend (`profileService`/`branchService`/`paymentService`/`attendanceService` "get all" endpoints) with Supabase fallback; everything else (all of Owner's KPI queries, Trainer, Receptionist) talks directly to Supabase from the client. Since all three Supabase hosts are NXDOMAIN and the ngrok tunnel is dead, every widget on every dashboard currently renders zeros/empty after silent console.log failures.

## What actually works

The render layer is in decent shape: consistent theming via `createStyles(colors)` + `useMemo`, dark-mode aware, sensible card/tile composition, charts wrapped in horizontal ScrollViews, most lists have explicit empty-state copy ("No trainers yet", "No payments found"), PaymentsScreen has a real loading/empty/list tri-state, and the Owner "ALL vs single branch" gating correctly hides single-branch-only actions (renew toggle, quick actions) in aggregate view. Trainee/group cards on TrainerDashboard have nice pressed-state affordances. The plan-tab loader on Owner correctly resolves the initial tab before fan-out loading.

## UI & design notes

- OwnerDashboard is the visual flagship but is a 1,941-line monolith; chart width `screenWidth * 1.6` forces horizontal scroll even on wide web viewports where it could fit.
- Hardcoded hex colors bypass the theme in many places: `#000` text on accent buttons, `#4ecdc4`/`#ff6b6b`/`#ffd93d`/`#ff9ff3` tile colors, `#555` star color, `#0f0`/`#f55` status colors (ReceptionistDashboard:267-269), `"#fff"` icons in Owner modal headers (line 1260, 1337) which will be invisible-on-light if theme switches.
- ReceptionistDashboard QuickButton text is `#fff` on `colors.accent` — likely fails contrast in light theme if accent is bright.
- Member lists are `.map()` inside ScrollView everywhere (no FlatList/virtualization) — Owner plan members, Admin users (4 lists), payments (100 rows) all render eagerly; on web this is acceptable but on device it will jank with real data.
- PaymentsScreen has the best state handling of the slice (loading/empty/filter) and could be the template for the rest.
- No pull-to-refresh on any dashboard; the only way to refresh is to re-mount.

## Cross-slice questions

1. services/ slice: confirm `branchService.getAllBranches`, `paymentService.getAllPayments`, `profileService.getAllProfiles`, `attendanceService.getAllAttendance` really are unscoped list-all endpoints and whether `options.useAuth` is even set for them (S2). If unauthenticated, every cross-tenant leak above is pre-auth, not just IDOR.
2. components/ slice: what does the QR scanner (QRCodeModal / trainee scan flow) validate? If it accepts the static `ATTENDANCE_GATE_QR` string with no branch/time check, the static QR finding escalates to HIGH.
3. components/RenewSubscriptionModal: confirm which `payment_mode` and `status` values it writes ("CASH", "Completed"?) — determines whether PaymentsScreen "Pending" filter can ever match anything.
4. backend slice: is there a `get_user_emails_by_role` RPC defined with SECURITY DEFINER in Supabase SQL? That would let any authenticated client enumerate all user emails regardless of UI.
5. server/ slice: confirm `ENDPOINTS.SEND_EMAIL` (Brevo service) has no auth and no rate limiting — Receptionist broadcast calls it bare.
6. navigation slice: `QRScanner` route (AppNavigator.js:44) appears unreachable — confirm nothing navigates to it.
