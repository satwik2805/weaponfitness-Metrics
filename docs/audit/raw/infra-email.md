# Audit slice: infra-email

## Purpose (what this slice does)
This slice covers the out-of-band infrastructure that the React Native app leans on:

- **`server/`** — a standalone Node/Express "Email Server" (port 5000) that (a) exposes `POST /api/email/send` to blast branded HTML email via the Brevo HTTP API, (b) exposes `POST /api/email/test-absent-reminder` to manually trigger the absent-trainee reminder, and (c) runs a `node-cron` job at 09:00 daily that emails trainees who have not attended in >=3 days (via Brevo SMTP through nodemailer).
- **`supabase/functions/rate-limit-demo/index.ts`** — a Supabase Edge Function that, despite its name, is the app's **privileged write gateway**. It is invoked by ~12 client components (`AddTrainerModal`, `RegisterMemberModal`, `ManagePlansModal`, etc.) and performs admin-level mutations (create auth users, insert profiles/branches/plans, assign workouts/diets, mark attendance, submit feedback) using the Supabase **service-role key**, plus Upstash Redis sliding-window rate limiting.
- **`Dockerfile` / `docker-compose.yml`** — intended to containerize the Expo dev server.
- **`run_project.py`** — Windows dev launcher that kills ports 8000-8002 and boots the FastAPI backend (port 8002) + Expo.
- **`.gitignore`, `README.md`, `SYSTEM_ARCHITECTURE.md`, `WORKOUT_TRACKING_README.md`** — repo hygiene + docs.
- **`android/app/build.gradle`, `android/app/src/main/AndroidManifest.xml`** — native Android build config and manifest.

## What actually works
- `server/index.js` is a clean, conventional Express bootstrap: env-var validation gate (fail-fast on missing vars), request logging, 404 + error handlers, graceful SIGTERM/SIGINT shutdown, uncaughtException/unhandledRejection hooks. This part is solid.
- The Edge Function's rate-limit map (per-route sliding windows, JWT-or-IP identity resolution) is reasonable and would work if Upstash + Supabase are alive.
- `emailController.sendEmailToUsers` validates recipients/subject/message shape before sending.
- AndroidManifest is a standard Expo-generated manifest; deep-link scheme `weaponfitness` is wired correctly and matches the README.
- `.gitignore` is broad and mostly correct for an Expo + Python repo.

## Findings

| severity | file:line | issue | impact | suggested fix |
|----------|-----------|-------|--------|---------------|
| CRITICAL | supabase/functions/rate-limit-demo/index.ts:154-1014 | The Edge Function performs every privileged mutation with the **service-role key** but performs **NO authorization check** that the caller is an admin/owner. It trusts client-supplied IDs (`trainerId`, `ownerId`, `creator_id`, `branchId`, `payloadTraineeId`). Identity is resolved (line 116-123) only for rate-limit keying, never for authz. | Any client holding the public anon key can call `add_trainer`/`add_receptionist`/`add_branch`/`create_trainee` to create confirmed auth users (with attacker-chosen or default password `12345678`, line 388) and seed staff/owner records — full account/privilege fabrication and IDOR across the whole admin surface. | Verify the JWT, load the caller's role from `profiles`, and reject when the action exceeds the caller's role; never accept `ownerId`/`creator_id` from the body — derive from the verified token. |
| CRITICAL | supabase/functions/rate-limit-demo/index.ts:270-273 | `create_group` silently **upgrades any user to `Trainer`** (`profiles.update({role:'Trainer'})`) when the supplied `trainerId` lacks that role, and auto-creates a `trainers` row (284-289). | Self-service privilege escalation: a trainee can promote themselves (or anyone) to Trainer by invoking create_group with their own id. | Remove the auto-upgrade; reject if the caller is not already an authorized trainer/admin. |
| CRITICAL | server/.env (tracked in git; commit 177214f) | `server/.env` is committed and contains live secrets: SUPABASE_URL, SUPABASE_ANON_KEY, SMTP_HOST/PORT/LOGIN/**SMTP_KEY**, **BREVO_API_KEY**, SENDER_EMAIL. `.gitignore` lists `.env` but the file was committed before that rule, so it remains tracked. | Brevo email-send credentials + SMTP key leaked in history → attackers can send mail as Weapon Fitness (phishing/spam, sender-reputation burn). Extends seed S1. | Rotate the Brevo API key + SMTP key immediately; `git rm --cached server/.env`; purge from history; add explicit `server/.env` to `.gitignore`. |
| CRITICAL | server/routes/emailRoutes.js:13; server/controller/emailController.js:3-43 | `POST /api/email/send` has **no authentication** and accepts an arbitrary `recipients[]`, `subject`, `message`. The server wraps the message in Weapon Fitness branding and sends via Brevo. | Open email relay: anyone who can reach the server can send branded phishing/spam to arbitrary addresses, exhausting the Brevo quota and damaging domain reputation. | Require an authenticated admin token; restrict recipients to known trainees; rate-limit. |
| HIGH | server/cron/absentReminder.js:50,59-62,73-84,94-100 | The cron callback calls **`res.json(...)` / `res.status(...).json(...)` but there is no `res` object** in a cron context (`res` is undefined). Any branch that hits these lines (no absentees, RPC error, or empty recipient list — the common cases) throws `ReferenceError: res is not defined`, which becomes an unhandledRejection. | The daily 09:00 absent-reminder job crashes on its normal/most-frequent paths and never completes cleanly; reminders are unreliable. Looks copy-pasted from the Express test route without removing `res`. | Replace all `res.*` calls with `console.log`/`return`; the cron handler must not reference `req`/`res`. |
| HIGH | server/cron/absentReminder.js:6-9 | Supabase client built with `SUPABASE_ANON_KEY` (code comment even says "MUST be service key"). RPC `get_user_emails_with_id_by_role` and reads of `profiles`/`attendance` will be governed by RLS as anon. | Under RLS the anon key likely cannot enumerate all trainees or fetch emails via the RPC, so the cron silently returns empty/forbidden and emails are never sent — the feature is effectively broken even after the `res` bug is fixed. | Use the service-role key (server-side only) for the cron's Supabase client. |
| HIGH | server/index.js:21-27 vs server/utils/sendEmail.js:9-11 | Env validation requires `BREVO_API_KEY`+`SENDER_EMAIL` (HTTP-API path) but **does not require `SMTP_LOGIN`/`SMTP_KEY`**, which the cron's `sendEmail` (nodemailer SMTP) actually uses. The app mixes two send mechanisms: controller uses Brevo HTTP API, cron uses SMTP. | If SMTP creds are absent the server still starts and passes validation, but `transporter.verify()` fails and the cron's emails throw at send time — inconsistent/partial failure that is hard to diagnose. | Validate all secrets actually used; standardize on one send mechanism. |
| HIGH | server/routes/emailRoutes.js:16-110 | `POST /api/email/test-absent-reminder` is **unauthenticated** and triggers a real mass-email send to all absent trainees. | Anyone reachable can spam every absent trainee on demand and burn Brevo quota; also leaks trainee IDs/emails in the `debug` response (lines 82-88). | Remove the test route from production or guard it behind admin auth; never return raw email/ID lists. |
| HIGH | Dockerfile:1; package.json:25,46 | Base image is `node:18`, but the project is **Expo SDK 54 / React Native 0.81.5**, which requires Node 20+. | `npx expo start` will warn/fail under Node 18; the container is unlikely to build/run the current SDK. | Bump to `node:20` (or `node:22`). |
| HIGH | docker-compose.yml:1-16; Dockerfile:9-13 | The container only runs `npx expo start -c` for the **frontend**; it does NOT build/run the Node email server (`server/`) or the Python FastAPI backend (`backend/`). `COPY package*.json` + `npm install` installs only root deps, not `server/`'s. Compose mounts `.:/app` over the image, masking the installed `node_modules`. There is no requirements.txt for the backend (confirmed: backend/ has none). | "Dockerized" setup is incomplete and will not bring up a working stack; the bind mount also defeats the cached `npm install`. Docs implying a one-command Docker boot are misleading. | Provide separate services (frontend/email-server/backend) or document that compose only runs Expo; fix the volume/install ordering; add backend dependency manifest. |
| MEDIUM | server/index.js:10 | `app.use(cors())` enables CORS for **all origins** with default settings on the email server. | Any website can POST to the (unauthenticated) email endpoints from a browser. Extends seed S4 (CORS `*`). | Restrict `origin` to the app's known hosts; combine with auth. |
| MEDIUM | supabase/functions/rate-limit-demo/index.ts:91,139,237 etc. | Edge Function sets `Access-Control-Allow-Origin: *` on every response. | Same cross-origin exposure of a privileged endpoint. Extends S4. | Lock the allowed origin list. |
| MEDIUM | supabase/functions/rate-limit-demo/index.ts:101-107 | Rate-limit bucket is chosen from a **client-controlled** `x-action-path` header (falls back to URL path). | A caller can send `x-action-path: /admin_write` (30/min) — or any high-limit/unknown path that resolves to `default` 60/min — while invoking a sensitive action gated for a low limit (e.g. `/signup` 3/h, `/otp`). The rate-limit preset is fully bypassable. | Derive the limiter key from the server-trusted `action` value, not a client header. |
| MEDIUM | supabase/functions/rate-limit-demo/index.ts:1029-1040 | Global catch returns `err.message` to the client. | Leaks internal/Postgres error detail to callers. Mirrors seed S5 (stack traces) on the edge tier. | Return a generic message; log details server-side only. |
| MEDIUM | supabase/functions/rate-limit-demo/index.ts:933 | `submit_feedback` calls `supabase.auth.getUser()` with no token (commented confusion in 933-952), then ignores the result and trusts `payload.traineeId`. Dead/abandoned auth attempt. | Feedback can be submitted on behalf of any trainee id (IDOR); the half-written getUser call is dead code. | Verify the JWT and use its user id as `trainee_id`. |
| MEDIUM | server/index.js:122-124 | `unhandledRejection` handler logs but does **not** exit, while `uncaughtException` exits. | MEDIUM | server/cron/absentReminder.js:25-46 | N+1 query pattern: one `attendance` query **per trainee** in a serial loop on every run. | Does not scale; slow/expensive as the gym grows. | Single aggregate query (max(date) grouped by trainee) or an RPC. |

## UI & design notes
Not applicable to this slice (infra/server/docs/native config only). One indirect UX note: because the cron + RPC chain is broken (anon key + `res` bug), the "We Miss You at the Gym" re-engagement emails advertised in the docs never actually send, so trainees silently get no reminders.

## Dead code & hygiene
- **`supabase/.temp/cli-latest`** is tracked in git (Supabase CLI scratch file) — should be ignored.
- `server/cron/absentReminder.js` is a near-verbatim copy of the `test-absent-reminder` route in `emailRoutes.js`, including the inapplicable `res.*` calls — duplication that caused the HIGH bug.
- `submit_feedback`'s `supabase.auth.getUser()` block (rate-limit-demo/index.ts:933-952) is dead/abandoned with multi-line "thinking out loud" comments left in production code.
- The terminal `return new Response({success:true, remaining, data: body})` (index.ts:1016-1028) echoes the **entire request body** back to the caller for any unrecognized `action` — debug behavior that leaks input.
- README.md is stale: it documents `config/supabase.js` editing and Google OAuth setup, but says **nothing** about `server/` (email server), `backend/` (FastAPI), the Edge Function, `run_project.py`, ngrok, or the actual multi-tier architecture. It describes the app as a simple Welcome/Login Expo app.
- WORKOUT_TRACKING_README.md references six docs (`IMPLEMENTATION_SUMMARY.md`, `WORKOUT_TRACKING_GUIDE.md`, `API_QUICK_REFERENCE.md`, `IMPLEMENTATION_CHECKLIST.md`, `INTEGRATION_EXAMPLE.js`) and two backend scripts (`backend/test_workout_tracking.py`, `backend/create_workout_tables.py` — only the latter exists). Most of the referenced docs/scripts are **absent** from the repo. It also tells users to integrate `<WorkoutTracker>`/`<WorkoutReminderSettings>` into `TraineeHomeScreen.js` as if not yet wired (status unclear vs reality).
- SYSTEM_ARCHITECTURE.md describes APScheduler "every 1 minute" workout/sleep reminder jobs in the FastAPI backend with "Send Notification (To Be Implemented)" — i.e. the documented reminder system is explicitly unimplemented at the notification step.
- `run_project.py` hardcodes Windows PowerShell port-kill commands and backend port **8002**, while `config/api.js` (per ground truth) points at a hardcoded offline ngrok URL — the dev launcher and the app's API base are not aligned.
