# Slice: backend-api-2

Files: backend/app/api/{profile.py, push_token.py, sleep_reminder.py, sleep.py, trainee.py, trainer_attendance.py, trainer.py, workout_log.py, workout_reminder.py, routes/__init__.py, __init__.py}

## Purpose
CRUD/REST routers for the core domain entities and trackers: profiles (Supabase auth-linked users), trainers, trainees, sleep logs + sleep reminders, workout logs + workout reminders, trainer attendance, and Expo push-token registration/test notifications. All routers use the SQLAlchemy `Session` from `app.core.database.get_db`, return Pydantic response models, and are mounted in `backend/main.py` (lines 50-67). `routes/__init__.py` and `api/__init__.py` are both empty (0 bytes).

## What actually works
- Standard CRUD shape is consistent and correct per-entity: get-by-id and delete properly 404 when the row is missing; list endpoints return all rows.
- Sleep create/update (sleep.py) carefully strips tzinfo from `time` columns and normalizes `deep_sleep_rating` (0 / out-of-range -> NULL) to satisfy a DB CHECK constraint; score/minutes auto-derived. This is genuinely defensive code.
- `trainer_attendance.create` is idempotent per (trainer_id, date): updates the existing row instead of duplicating (lines 24-33).
- `sleep_reminder.create` enforces single-active-reminder by deactivating prior active rows (lines 18-25).
- XP award and consistency updates are wrapped in try/except so a tracking failure does not break the primary write (sleep.py, workout_log.py).
- Push token save delegates to a service; Expo send path handled by a dedicated service module.
