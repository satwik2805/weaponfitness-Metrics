# Audit — components-modals-2

Slice: 20 modal/settings components in `components/` (GroupDetailModal, LevelUpModal, ManagePlansModal, ManageWorkoutsModal, MonthlyPlanModal, NutritionTrackerModal, PersonalAssignmentModal, QRCodeModal, QRScannerModal, RegisterMemberModal, RenewSubscriptionModal, SleepTrackingModal, TraineeDietModal, TraineeProfileModal, TraineeProgressModal, TrainerAttendanceModal, WeeklyDietAssignmentModal, WeeklyPlanModal, WorkoutModal, WorkoutReminderSettings). All 7,945 lines read.

## Purpose

These are the trainer/owner/trainee workflow modals: group management (members + delete group), membership plan CRUD, workout-template management and assignment (weekly/monthly, group/personal), diet assignment and viewing, nutrition logging (manual + AI parse + camera), sleep logging and bedtime reminders, attendance (QR display, QR scan, manual mark present/absent for trainees and trainers), member/trainer registration, subscription renewal, trainee progress dashboards (attendance calendar, sleep, nutrition, BMI), level-up celebration, and workout reminder settings. Data paths split three ways: direct Supabase table reads/writes, a `rate-limit-demo` Supabase Edge Function "gateway", and the FastAPI backend via `config/apiClient.js` or service wrappers.

## What actually works

Consistent theming via `useTheme()` + `createStyles(colors)` memoization in most files. The multi-select day/template UX in WeeklyPlanModal and MonthlyPlanModal is coherent (toggle, clear-day, save). Edge-function error unwrapping (`funcError.context.json()`) is done carefully and uniformly across the gateway callers. SleepTrackingModal handles create-vs-edit mode cleanly and computes total hours with overnight wraparound. TraineeProgressModal's calendar layout logic (padding weeks) is correct structurally. Several flows (TraineeProgressModal, WeeklyPlanModal, WeeklyDietAssignmentModal, SleepTrackingModal) correctly special-case `Platform.OS === 'web'` with `window.confirm`/`window.alert` — proof the team knows RN-web `Alert.alert` is broken, which makes the files that don't do this clear bugs.

## UI & design notes

- Visual language is inconsistent across modals: border radii range 10-30, overlay opacities 0.5-0.85, three different save-button styles (`colors.success` in ManagePlansModal vs `colors.accent` everywhere else), and text-on-accent is hardcoded `#000` in ~10 files while NutritionTracker/Sleep use `colors.primary` — a theme switch would break contrast in half of them.
- WeeklyDietAssignmentModal.cardSelected uses hardcoded `rgba(255,100,100,0.15)` (red tint) while WeeklyPlanModal uses green `rgba(0,200,150,0.15)` for the identical "selected" affordance.
- Emoji-heavy alerts ("🎉", "❌", "✅ Success") read unpolished for a premium product.
- TraineeDietModal hardcodes `#fff` / `rgba(255,255,255,0.4)` text (lines 209, 219) — broken in a light theme.
- "Today is {selectedDay}" label (TraineeDietModal.js:136-137) is wrong after the user taps another day — it shows the selected day, not today.

## Cross-slice questions

1. **Edge function slice**: does `rate-limit-demo` verify caller role (owner vs trainer vs trainee) per action (`delete_group`, `manage_plans`, `add_trainer`, `add_trainee`, `renew_subscription`, `admin_attendance`)? Client sends raw IDs and chooses its own `x-action-path` rate bucket.
2. **DB/RLS slice**: are RLS policies present on `group_weekly_workouts`, `group_monthly_workouts`, `custom_trainee_weekly_workouts`, `group_weekly_diet`, `custom_trainee_diet`, `workout_templates`, `attendance` that bind writes to the owning trainer/branch? All are written directly from the client here.
3. **Services slice**: does `nutritionService.getDailySummary` always return `goals`? Does `sleepService` compute `score`? Does `sleepReminderService.createReminder` upsert (or do repeated "Update" taps create duplicates)? Do `/workout-reminders/*/toggle` (POST) and `/sleep-reminders/*/toggle` (PUT) match backend route verbs?
4. **Backend slice**: `attendanceService.markAbsent(traineeId)` and `trainerAttendanceService.*` — auth required? IDOR via path trainee id?
5. **Screens slice**: TraineeHomeScreen validates the QR string client-side only — confirm the attendance insert that follows is also unguarded server-side.
